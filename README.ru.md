Kanon превращает задачу агента в чеклист приёмки **до начала работы**:
наблюдаемые результаты, проверки и доказательства, которыми закрывается каждый
пункт. Файл сохраняет требования и решения после сжатия контекста, смены сессии
или исполнителя.

Это плагин для Claude Code и Codex с небольшим Python CLI. Название происходит
от греческого κανών — измерительной линейки плотника.

## Зачем

Собранный материал может исчезнуть из рабочего контекста, пока реализация
продолжается. План бывает выполнен, а запрошенного экрана, варианта или
ограничения в результате всё ещё нет. Kanon записывает результаты, пока материал
свежий, и показывает отсутствие доказательств и незаполненные слоты на приёмке.

## Пример

Пункт закрывается добавлением доказательства:

```markdown
- [ ] 1. Все запрошенные экраны помещаются на 360 px · проверка: скриншоты браузера
- [x] 2. Импорт сохраняет существующие записи · проверка: регрессия импорта · подтв: reports/import.txt
```

`[x]` с `подтв: сделано` остаётся открытым. Число в задаче становится таким же
числом слотов приёмки. Собранные ограничения и попытки, которые закончились
провалом, остаются в том же файле. [Полный формат](SPEC/FORMAT.ru.md).

## Установка

Claude Code:

```text
/plugin marketplace add ZenonEl/kanon
/plugin install kanon@kanon
```

Codex:

```bash
codex plugin marketplace add https://github.com/ZenonEl/kanon.git
codex plugin add kanon --marketplace kanon
```

Линтеру и хукам нужен Python 3.10+. CLI уборки требует Linux/macOS с POSIX
дескрипторами каталогов. [Установка и проверка](docs/INSTALL.ru.md) описывают
доверие хукам, локальную разработку и пути к скриптам.

## Работа

1. Собрать материал и записать чеклист до начала производства.
2. На каждой строке оставить один наблюдаемый результат с проверкой или явной пометкой «без проверки».
3. Закрывать пункты доказательствами; сохранять попытку и дословный результат провала.
4. На приёмке прочитать каждый пункт и доказательство. Перечислить незакрытое.
5. Явно архивировать неактивную задачу, чтобы она не оставалась в рабочем списке навсегда.

В Claude Code доступны `/kanon:open`, `/kanon:close`, `/kanon:accept`,
`/kanon:sweep` и `/kanon:retire`. В Codex те же операции доступны через навык
`task-to-checklist` и скрипты.

## Уборка без ложного закрытия

Активные файлы лежат в `_kanon/`, архивные — в `_kanon/archive/`.
Архивирование требует причины и источника решения: задача **отложена**,
**отменена**, **заменена** или **выполнена**. Только последнее означает,
что все пункты имеют доказательства. Для отложенной работы нужны адрес
продолжения и условие возвращения.

`retire.py` сначала показывает план любой изменяющей операции. `--apply`
архивирует, восстанавливает или удаляет один выбранный файл. Восстановление
возвращает исходные байты. Удаление сначала сохраняет след решения и требует
адресов, где остались доказательства. Возраст ничего не удаляет автоматически.
[Примеры уборки](docs/CLEANUP.ru.md).

`_kanon/` не должен попадать в git: в своём проекте используйте `.gitignore`,
в общей репе — `.git/info/exclude`. Чеклисты — рабочие данные.

## Сенсоры

| Часть | Назначение |
|---|---|
| `check-checklist.py` | Отказывает при пустом доказательстве, неразобранных пунктах и несовпадении числа слотов |
| `sweep.py` | Показывает заброшенные и истёкшие файлы, пересобирает активный индекс |
| Хуки | Показывают заброшенное при старте, напоминают один раз перед производством без чеклиста и перечисляют открытые пункты при остановке |
| `retire.py` | Явное архивирование, восстановление, просмотр архива и окончательное удаление |

Хуки ничего не блокируют. Внутренняя ошибка хука даёт выход 0; напоминание
перед производством звучит максимум один раз за сессию. Архив не попадает
в активные напоминания. Автоматический выбор навыка ещё проверяется:
сама установка не доказывает, что он сработает на каждой подходящей задаче.

## Языки

Основная публичная документация английская; рядом есть русские переводы.
Инструкции агенту и технические контракты — английские. Чеклист и общение
агента следуют языку пользователя; цитируемые доказательства не переводятся.
Сообщения CLI и хуков, а также индексы по умолчанию английские. Канонические
ключи остаются ASCII; парсер принимает английские и русские псевдонимы.

## Границы

Kanon проверяет полноту по записанному чеклисту. Он не оценивает вкус,
правильность разложения задачи или подлинность доказательств. Закрытый
чеклист не заменяет ревью кода и приёмку человеком.
