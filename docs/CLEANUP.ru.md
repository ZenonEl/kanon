# Уборка чеклистов

**Лицензия:** [CC BY-SA 4.0](../SPEC/LICENSE) · [English](CLEANUP.md)

## Выбрать решение

Чеклист с одним-двумя незакрытыми пунктами не обязан оставаться в активном
списке навсегда. Нужно определить, что стало с задачей:

| Решение | Что сохраняется |
|---|---|
| Отложена | Открытые пункты, попытки, адрес продолжения и условие возвращения |
| Отменена | Открытые пункты и решение владельца об отмене |
| Заменена | Открытые пункты и адрес замены, где они сохранены |
| Выполнена | Доказательства каждого пункта и адреса для ценного материала |

Архивирование не закрывает незавершённый пункт. Сложность, тишина и прошедшее
время не разрешают отменять задачу. Уже принятое владельцем решение применяется
без повторного вопроса; новое нужно, если решения нет или меняется согласованный
объём работы.

## Посмотреть план и архивировать

Запускать из рабочего проекта. Вместо `/path/to/kanon` указать путь
установленного плагина. Флаги канонические, причина и источник решения —
на языке пользователя.

```bash
python3 /path/to/kanon/scripts/retire.py archive _kanon/task.md \
  --disposition deferred \
  --reason 'Возвращаемся после запуска' \
  --decision-source 'issue #42, решение владельца' \
  --continued-in 'issue #43, оставшиеся пункты' \
  --revisit 'После запуска'
```

Без `--apply` команда только показывает план. Проверить, что issue #43
существует и сохраняет оставшуюся работу и попытки; затем добавить `--apply`
к той же команде, если решение уже разрешено.

Для отмены — `--disposition cancelled`, причина и источник решения.
Для замены — `--disposition superseded` и `--continued-in`.
Для выполненной задачи — `--disposition completed`: CLI отказывает при открытых
пунктах и ошибках линтера. Он не ставит дату закрытия и не создаёт доказательства.

Имя архивного файла включает дату, исходное имя и начало хеша содержимого.
Исходные байты и запись решения сохраняются. Существующий файл не затирается.
`_kanon/archive/` не попадает в активные напоминания.

## Посмотреть архив и вернуться к работе

```bash
python3 /path/to/kanon/scripts/retire.py report
python3 /path/to/kanon/scripts/retire.py restore _kanon/archive/<archived-file>.md
```

Отчёт показывает решение, число открытых пунктов, причину, источник решения
и продолжение. Через 30 дней предлагает ручной пересмотр. Ничего не удаляет.
`restore` сначала показывает план; с `--apply` возвращает исходные байты
и сохраняет решение в журнале архива. Активный файл с таким же именем
не затирается.

Активный индекс ссылается на архив. Отложенная задача всё ещё нужна:
отсутствие напоминаний Stop не означает, что она сделана.

## Окончательно удалить файл

Сначала перенести ценные доказательства в долгоживущее место. Проверить, что
отложенная или заменённая работа сохранилась по адресу продолжения.
Затем посмотреть план:

```bash
python3 /path/to/kanon/scripts/retire.py purge _kanon/archive/<archived-file>.md \
  --evidence-in 'issue #43 и reports/final.txt'
```

CLI требует `--evidence-in`, если в файле есть доказательства. Он проверяет
наличие адресов, а не содержание внешнего материала: назначения нужно прочитать
до применения. `--apply` добавляется, когда разрешено именно это удаление.

До удаления `archive/LOG.md` сохраняет задачу, решение, его источник, текст
незакрытых пунктов, провалы и оставшиеся адреса. Ошибка журнала запрещает
удаление. Этот короткий след остаётся при уборке. Возраст не запускает purge;
ни одна команда не удаляет каталог рекурсивно.

## Ошибки и ограничения платформы

CLI уборки использует файловые API Linux/macOS. Он отказывает при ссылках
на исходник или журнал, специальных файлах, ссылке вместо каталога архива
и совпадении имён. Хеш защищает от восстановления изменённого архива.
Если исходник изменился после записи назначения, обе копии остаются для проверки.

Команды уборки сериализуются файловой блокировкой. Во время изменения
не редактируйте тот же файл другим инструментом: посторонние писатели
не участвуют в блокировке. Архивы и журналы остаются рабочими данными
и не попадают в git. [Нормативный контракт, EN](../SPEC/RETIREMENT.md).
