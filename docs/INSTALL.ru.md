# Установка

**Лицензия:** [CC BY-SA 4.0](../SPEC/LICENSE) · [English](INSTALL.md)

## Требования

Python 3.10+, без дополнительных пакетов. CLI архивирования, восстановления
и удаления требует POSIX дескрипторов каталогов и файловых блокировок
(Linux/macOS).

Claude Code использует навык и пять слэш-команд. Codex — навык и скрипты.
Оба хоста могут загружать `hooks/hooks.json`; запуск хуков зависит от доверия
и настроек хоста. Автоматический выбор навыка проверяется отдельно.

## Claude Code

В Claude Code:

```text
/plugin marketplace add ZenonEl/kanon
/plugin install kanon@kanon
```

Проверьте через `/plugin`, что Kanon включён. Для локальной разработки
зарегистрируйте каталог репозитория как маркетплейс:

```text
/plugin marketplace add ./kanon
/plugin install kanon@kanon
```

Обновление установленной копии идёт штатным способом хоста; после обновления
перезапустите сессию. Правка рабочего репозитория сама по себе не обновляет
установленный кэш.

## Codex

```bash
codex plugin marketplace add https://github.com/ZenonEl/kanon.git
codex plugin add kanon --marketplace kanon
```

Такая форма команд соответствует справке локального CLI. Копирование каталога
само по себе не регистрирует маркетплейс. Установку можно посмотреть через
`codex plugin list`, а доверие хукам — в настройках хуков хоста.

Совместимость хуков измерена на Codex 0.149.0 3 сентября 2026 года: shell
приходил как `Bash`, патчи — как `apply_patch`, `systemMessage` был виден.
Это зафиксированный замер, а не обещание для всех будущих версий хоста.
Если хуки отсутствуют или выключены, навык и явный CLI остаются доступны.

## Пути к скриптам

Скрипты принадлежат плагину, а не рабочему проекту. Вызывайте их из каталога
этого проекта, указывая абсолютный путь установленной копии.

Типичный путь кэша Codex:

```text
~/.codex/plugins/cache/<marketplace>/kanon/<version>/scripts/
```

У Claude Code похожий кэш в `~/.claude/plugins/cache/`. Найдите фактическую
версию: рабочий checkout не обязательно совпадает с установленным.
Хост передаёт `${CLAUDE_PLUGIN_ROOT}` командам хуков; в обычном shell переменной
может не быть. Тогда используйте проверенный путь кэша.

После определения пути:

```bash
python3 /path/to/kanon/scripts/check-checklist.py
python3 /path/to/kanon/scripts/sweep.py
python3 /path/to/kanon/scripts/retire.py report
```

`/path/to/kanon` — заполнитель. Изменяющие команды описаны в [уборке](CLEANUP.ru.md).
Сообщения CLI и хуков по умолчанию русские; общение агента следует вашему языку.

## Хуки

| Событие | Вывод |
|---|---|
| `SessionStart` | Заброшенные активные чеклисты и закрытые файлы, которые пора пересмотреть |
| `PreToolUse` | Одно напоминание, когда после минимум трёх собирающих вызовов началось производство без активного чеклиста |
| `Stop` | Активные пункты, которые открыты или отмечены без доказательства |

Запись — `Write`, `Edit`, `NotebookEdit`, пишущие Bash-команды и `apply_patch`.
Читающие Bash-команды считаются сбором. Собственный счётчик Bash покрывает
сессии без совместимого транскрипта.

Напоминание молчит при записи самого чеклиста, при наличии открытого или
заброшенного чеклиста, ниже порога сбора и после первого напоминания. Архив
не вызывает активных напоминаний. Ни один хук не блокирует работу; внутренняя
ошибка даёт выход 0. Пороги намеренно сохранены.

## Проверка и диагностика

В свежей сессии дайте обычную задачу со сбором материала и последующим
производством, не называя Kanon. Посмотрите, выберется ли навык и появится ли
чеклист до реализации. Ручной вызов фиксируется отдельно: автоматический
выбор он не доказывает.

1. Навыка нет в списке: проверить регистрацию маркетплейса, включённость,
   `skills/task-to-checklist/SKILL.md` и frontmatter.
2. Навык есть, но не выбран: записать точный промпт и версии плагина и хоста.
   Маршрутизация читает описание; проверка формы не диагностирует выбор.
3. Навык выбран на мелкой правке: сверить порог применения до объявления бага.
4. Хуки молчат: проверить доверие и настройки хоста, затем приход совместимого
   события. Рабочий Stop не доказывает автоматический выбор навыка.

Из рабочего checkout:

```bash
python3 scripts/check-skills.py
```

Это проверка формы. Живой выбор измеряется наблюдением или прогоном маршрутизации
с сопоставимой сессией без плагина; доступность eval здесь не обещается.

## Рабочие файлы

Добавьте `_kanon/` в `.gitignore` своего проекта или `.git/info/exclude` общей
репы. Сам плагин можно хранить в git; чеклисты, архивы и журналы содержат рабочие
материалы и не попадают в коммиты.

Другой каталог задаётся через `KANON_DIR`. В worktree чеклист пишется там, где
идёт работа, либо сессия направляется в этот каталог. Поиск нерекурсивный:
`archive/` отделён от активного списка, а `INDEX.md` — производный файл.
