# Формат чеклиста

**Версия формата:** 0.3
**Статус:** перевод. Нормативный документ — [`FORMAT.md`](FORMAT.md); при
расхождении верен он.
**Лицензия:** CC BY-SA 4.0 (см. [`LICENSE`](LICENSE))

Скилы, команды и скрипты этого репозитория — потребители формата. Расхождение
поведения инструмента с текстом — дефект инструмента, а не повод переписать
спеку.

## Язык

Чеклист пишется **на языке того, кто работает**. Машинные ключи ниже —
фиксированный ASCII, чтобы линтер разбирал файл независимо от этого языка.

У каждого ключа есть задокументированные псевдонимы. Линтер принимает любой;
новый язык добавляется строкой в таблицу, канонический ключ при этом не
меняется.

| Канонический | Принимаемые псевдонимы |
|---|---|
| `## Gathered` | `## Собрано`, `## Из собранного` |
| `## Acceptance` | `## Приёмка` |
| `## Failures` | `## Провалы` |
| `check:` | `проверка:` |
| `proof:` | `подтв:`, `подтверждено:` |
| `tried:` | `пробовал:` |
| `returned:` | `вернулось:` |
| `[no check]` | `[без проверки]` |

Ключи frontmatter всегда канонические и не переводятся.

## Расположение

```
_kanon/
├── INDEX.md                  производный — пересобирается sweep.py, руками не пишется
└── <YYYY-MM-DD>-<slug>.md    один чеклист на задачу
```

`_kanon/` — в корне рабочего проекта, добавляется в его `.gitignore`. Чеклист не
коммитится: он леса, а не результат. Всё, что должно пережить работу, к моменту
истечения обязано жить в другом месте.

Каталог **видимый, а не скрытый**: инструмент, который прячет свои файлы, прячет
и недостачу, ради показа которой заведён. Подчёркивание сортирует его наверх.

**Имя — рекомендация, а не правило.** `.kanon/` из ранних версий принимается,
`KANON_DIR` переопределяет оба. Проверка, чьи предупреждения учатся пропускать,
хуже отсутствующей.

`INDEX.md` производный. Правки в нём затираются следующим прогоном `sweep.py`.

`slug` — короткое имя задачи в kebab-case.

## Тело

```markdown
---
task: <задача одной строкой, как её поставили>
opened: YYYY-MM-DD
closed: YYYY-MM-DD | null
slots: <целое число | null>
source: <откуда материал: ветка, issue, экспорт, ссылка>
---

## Из собранного

- <требование или ограничение> · <откуда>
- <запрет> · <откуда>

## Приёмка

- [ ] 1. <наблюдаемый результат> · проверка: <команда | путь | коммит>
- [x] 2. <наблюдаемый результат> · проверка: <...> · подтв: <доказательство>
- [ ] 3. <наблюдаемый результат> · [без проверки]
- [ ] 4. <пустой слот, ожидает>

## Провалы

[!] 2 · пробовал: <действие> · вернулось: <дословно> · YYYY-MM-DD
```

## Правила

1. **Пункт формулируется как наблюдаемый результат, а не как действие.**
   «Шапка открывается на 360px» проверяемо; «сверстать шапку» — нет.

2. **Число в задаче становится числом слотов.** Если задача называет количество
   («три варианта», «десять экранов»), `slots:` его записывает, и в разделе
   «Приёмка» обязано быть столько же строк, включая пустые. Пустой слот виден;
   намерение «сколько получится» — нет.

   `slots: null` означает, что количество не называлось. Пропустить поле, когда
   оно называлось, — дефект: правило становится непроверяемым.

3. **Пункт закрывается доказательством, а не отметкой.** `[x]` без поля
   `подтв:` недействителен и читается как открытый. Доказательство — вывод
   команды, путь к файлу или скриншоту, хеш коммита, ссылка на прогон.
   «Сделано», «проверил», «работает» доказательствами не являются.

4. **Пункт без проверки разрешён, но помечен** `[без проверки]`. Запрещать
   нельзя: часть работы честно проверяется только глазами. Скрывать — тоже: в
   приёмке должно быть видно, какая доля результата ни на чём не держится.

5. **Провал оставляет след.** Переделка без записи в «Провалы» недопустима:
   следующая попытка обязана знать про предыдущие. Запись ссылается на
   существующий номер пункта.

6. **«Я помню» источником не является.** «Из собранного» заполняется до начала
   производства, пока материал ещё в контексте. Пустой раздел после фазы сбора —
   дефект.

## Состояния

Состояние **выводится**, а не хранится:

| Состояние | Условие |
|---|---|
| `closed` | `closed` непусто |
| `stale` | `closed` пусто И файл не менялся 14 дней |
| `open` | иначе |

Хранимый статус — утверждение, которому нечем возразить. Выведенное из даты и
содержимого проверяется.

## Срок жизни

| Состояние | Срок |
|---|---|
| `open` | не истекает |
| `closed` | 7 дней от даты `closed`, затем удаляется |
| `stale` | **не удаляется; показывается** с перечнем открытых пунктов |

Принцип: **истекает тара, а не содержимое.** К моменту истечения всё ценное
обязано жить не здесь — в коммите, в требовании, в findings-log.

Истечение работает и как проверка: файл, который жалко удалить, означает, что
доказательство никуда не переехало, то есть работа не закрыта.

Три исхода: `drop` — выбросить (по умолчанию для `closed`); `extract` — вытащить
доказательства в долгоживущее место, тару удалить; `keep` — сохранить целиком
(редко, чеклист сам стал документом).

## Необязательная привязка к реестру требований

Пункт приёмки может нести идентификатор внешнего требования:

```markdown
- [x] 2. <результат> · req: t042 · проверка: <...> · подтв: <доказательство>
```

Поле `подтв:` тогда — готовое значение для поля доказательства в том реестре.

Привязка односторонняя: kanon знает про реестр, реестр про kanon не знает и знать
не обязан. Его отсутствие ни на что не влияет.

## Что проверяет линтер

`scripts/check-checklist.py` проверяет форму, а не смысл:

- frontmatter на месте и разбирается, `opened` — валидная дата;
- `slots:` заполнен, когда задача называла количество, и совпадает с числом
  строк приёмки;
- нет `[x]` без `подтв:`;
- `подтв:` не из стоп-листа пустых утверждений, на любом поддерживаемом языке;
- записи провалов ссылаются на существующие номера;
- «Из собранного» не пуст.

Он не умеет судить, настоящее ли доказательство и верно ли выбран пункт. Машина
видит непустоту; отличить отчёт от «подтверждено: сделано» может только человек.
Поэтому приёмка печатает доказательства дословно, а не сообщает, что они есть.
